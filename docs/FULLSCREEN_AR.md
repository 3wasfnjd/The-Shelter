# ملء الشاشة عند بدء اللعب

- `src/systems/FullscreenManager.js`: طلب ملء شاشة المستند بما يشمل أدوات التحكم، كشف دعم المتصفح، زر دخول/خروج، ورسالة بديل Safari عند عدم الدعم. فشل الطلب لا يوقف اللعبة.
- `src/main.js`: الطلب من ضغطة دخول الغرفة قبل أي انتظار لتحميل الصوت، لأن المتصفح يشترط تفاعلًا مباشرًا.
- `index.html`: زر ملء الشاشة وبيانات التشغيل المستقل على iPhone ورابط manifest.
- `public/manifest.webmanifest`: فتح اللعبة المضافة للشاشة الرئيسية بوضع standalone ومسارات نسبية متوافقة مع Pages. لا يتضمن ذلك دعم اللعب دون إنترنت.
- `test/fullscreen.test.js`: التحقق من مسار الطلب الناجح ومسار عدم الدعم.
- هذا الملف: وصف التغييرات وحدود المتصفح.

اكتمال التحميل وحده لا يكفي لطلب ملء الشاشة؛ ضغطة دخول اللعبة هي التفاعل المطلوب. إذا منع Safari الطلب، استخدم مشاركة ثم إضافة إلى الشاشة الرئيسية وافتح اللعبة من أيقونتها. لا يمكن للكود إجبار المتصفح على إخفاء شريطه.

مراجع: https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen

مشكلة التحميل المنفصلة: النشر التقليدي من فرع main يعيد نشر src/main.js بلا بناء Vite. يلزم تغيير Settings → Pages → Source إلى GitHub Actions. الربط المتاح لا يقدم تعديل هذا الإعداد الإداري؛ إعادة نشر البناء تعالج النسخة الحالية فقط.
